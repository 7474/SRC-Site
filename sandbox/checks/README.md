# 動作確認（サンドボックスに足す、機能追加・不具合修正の確かめ）

SRC#（7474/SRC）と SRC#Site の機能追加・不具合修正を、本番の SRC#Web で確かめるための小さなステージを、ここに 1 つずつ足していく。

> 生成AIで作ったテスト用のシナリオの一部です（[サンドボックス](../README.md)）。

## 遊び方

1. サンドボックスで敵を倒し、インターミッションに進む
2. インターミッションの「動作確認」で確かめたいものを選ぶ（新しい順）。説明が出る
3. 「次のステージへ」で始まる。終わるとインターミッションに戻るので、続けて別のものを選べる

確かめ方は 2 種類。

| 確かめ方 | 内容 |
|---|---|
| 自動 | ステージが結果を調べ、「合格」「不合格」を出す |
| 目視 | 説明のとおりに画面を見て確かめる。正しい動作と、直す前の動作を説明に書く |

## 足し方

1. `YYYY-MM-DD-短い名前.eve` を作る（日付は 7474/SRC・7474/SRC-Site に入った日。同じ日に複数あれば名前で分ける）
2. 先頭に、下の見出しをコメントで書く（`scripts/make-sandbox.py` が読み、インターミッションのメニューと `確認一覧.md` を作る。足りなければ zip を作れない）
3. 本体は `スタート:` から書き、最後は `Continue ステージ\おわり.eve` でインターミッションに戻る。操作をしてもらうものは `Exit` で操作を渡し、マップコマンド「確認を終える」（`マップコマンド 確認を終える:`）で戻れるようにする
4. 要るデータは `data/` の `robot.txt`・`pilot.txt` に足す（`Data/確認/` に入り、最初のステージで `Load 確認` する）。部品の .eve は `lib/` に置く（`Lib/確認/` に入る）
5. 画面なしで通す手順を `YYYY-MM-DD-短い名前.play`（PlayScript。7474/SRC の docs/gui/e2e-testing.md）に書く。確認のステージが始まったところから、インターミッションに戻るまで。自動のものは `expect message`・`expect eval` で結果を確かめる。操作を渡すものは `cell`・`menu` で操作し、最後に「確認を終える」を選ぶ
6. `scripts/check-sandbox.sh <名前>.eve` で通してから PR にする（[サンドボックス](../README.md) の「画面なしで通す」）。CI でも通す

```
# 題: 確かめること（メニューに出る。30 文字くらいまで）
# 日付: 2026-10-27
# 種類: 修正 | 追加
# 関連: https://github.com/7474/SRC/pull/1330（空白で区切って複数）
# 確かめ方: 自動 | 目視
# 説明: 何をすると、どうなれば正しいか（直す前はどうだったか）。メニューで選んだときに出る
```

- ステージ同士は独立させる（ほかの確認の結果に頼らない）。マップは `sandbox.map`（12×10）、味方は `data/` の「確認係」を使う
- 変数は、ステージの中だけで使うものは `Local`、ラベルをまたぐものは `Global` にする。Info などの関数の引数の語（攻撃力 など）を変数の名前にしない
- 行の頭に「語:」と書くとラベルとして読まれる。会話の文では「は」「を」などでつなぐ
- 1 つのラベルに 1 つの本体を書く（ラベルを並べて本体を共有しない）
- 目視のものも、表示された文（`expect message`）や変数（`expect eval`）で確かめられるところは確かめる
- 古くなった確認も消さずに残す（回帰の確認になる）。仕様が変わって合わなくなったら直す
- 生成AIで作る場合も、作ったものはテスト用であることが分かるようにする（サンドボックス全体の決まり）
